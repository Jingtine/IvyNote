# v0.2.0-alpha — Workspace & Real File Management

Date: 2026-08-28

v0.2 extends the v0.1 foundation into a multi-mount Workspace with real file management. Users compose several existing local directories into one named Workspace without moving any files, control per-mount permissions and exclusion rules, perform safe create/rename/move/delete-to-Trash operations against real files, and get live external-change propagation from a Rust file watcher. Workspace config persists in the OS AppData directory as versioned JSON; user knowledge directories are never modified.

> This version is **not yet tagged**. Tagging `v0.2.0-alpha` is gated on a manual Windows 11 smoke run of the updated `README.md` checklist.

## Supported

- **Multi-mount Workspace** — compose existing local directories into one named Workspace without moving files; each directory is a *mount*. Welcome screen: New Workspace (name + first mount), Open Existing, Recent (last 8, one-click reopen).
- **Per-mount permissions** — each mount is `read-write`, `read-only`, or `excluded`:
  - read-only mounts show a lock marker, disable file operations in the UI, and are refused by Rust (`PermissionDenied`) — three-layer defense;
  - excluded mounts are not scanned, not watched, and never appear in the tree.
- **Exclusion rules** — default set from the spec (`.git`, `node_modules`, `dist`, `build`, `target`, `.venv`, `venv`, `.cache`, `coverage`), editable at workspace level and overridable per mount; the tree and the watcher honor them.
- **File operations against real files** — new folder, new Markdown, rename, same-mount cut/paste move, and delete-to-system-Trash. Rename/move never overwrite an existing target; names are validated (no separators, `.md` kept for Markdown). Read-only mounts refuse all of these in UI and Rust.
- **Delete → OS Recycle Bin** — deleted files go to the OS Trash via the Rust `trash` crate (see ADR 0004), recoverable with the standard OS restore flow. Permanent delete is not offered in v0.2.
- **Live file watcher** — one Rust `notify` watcher per readable mount, exclusion-aware, 300 ms debounce that coalesces bursts, emitting create/remove/rename events that update the tree live. The manual **Refresh** button remains as a forced full rescan.
- **Document follows renames** — renaming/moving an open document (in-app or externally) updates the editor to the new path, keeping your content and draft; deleting the open file externally shows the **missing-on-disk** state (saving disabled, draft kept).
- **Mount removal guard** — removing a mount closes its documents; a dirty document hits the unsaved-changes dialog first and removal waits for your decision.
- **Workspace config in AppData** — versioned JSON per workspace at `<AppData>/com.local-knowledge-ide.app/workspaces/<id>.json` (see ADR 0003); corrupt or unsupported-schema config fails safely with a clear `invalidWorkspaceConfig` error, never a silent rewrite.

## Deferred (not in v0.2)

- Link rewriting on rename/move — renamed/moved files keep their content but Markdown links pointing at them are not rewritten (v0.5, needs a link index).
- Cross-mount move, drag & drop, and multi-item selection operations — move is same-mount only in v0.2.
- SQLite / indexing / search — the AppData JSON config replaces no database; the index DB is deferred to v0.7.
- App-close confirmation guard — still open from v0.1: quitting with a dirty draft can lose the edit (file-switch and mount-removal are guarded, closing the window is not).
- Permanent delete UI — delete always goes to the system Trash; a double-confirmed permanent delete is a future feature.
- Binary/large-file filtering in the watcher.
- Fine-grained permissions beyond the three mount states.
- Still deferred from v0.1: Markdown preview/rendering, tabs (one document open at a time), note Properties panel, LaTeX (`.tex`) support, AI features.

## Notes for the Human Reviewer

- The automated suite (`pnpm verify`) covers the Rust config/store/scanner/ops/watcher layers, the typed IPC contracts, and the frontend flows. It does **not** touch a real OS Recycle Bin (the delete boundary is mocked; the real-trash test runs only with `IVY_TRASH_TEST=1`).
- Windows watcher behavior: `notify` reports renames on Windows as a `From` path followed by a `To` path; the watcher pairs them and degrades edge cases (an unmatched `To` → created, an unresolved `From` → removed). Renames crossing an exclusion boundary surface as the visible half of the change.
- A desktop smoke run is required before tagging: run the full updated `README.md` checklist (v0.1 steps 1–13 plus the new v0.2 steps) against `tests/fixtures/simple` and `tests/fixtures/multi` on Windows 11, including confirming a deleted file appears in the OS Recycle Bin.
- `tests/fixtures/multi` adds two mounts (`notes/`, `wiki/`), each with a top-level note, a nested note, and a `tmp/` dir holding a note — add `tmp` to the exclusions during the smoke run to verify per-mount exclusion behavior (it is not in the default set).
