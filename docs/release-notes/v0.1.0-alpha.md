# v0.1.0-alpha — Local Knowledge IDE Foundation

Date: 2026-08-27

This is the first alpha milestone of Local Knowledge IDE. It establishes the local-first file boundary: the app edits real local Markdown files through a Rust filesystem layer, with no database, no cloud, and no proprietary storage.

## Supported

- **Open one local directory** via the native folder picker (Tauri `dialog` plugin).
- **File tree** — nested directories and Markdown (`.md`) files are listed; non-Markdown files and ignored directories (`.git`, `node_modules`, `dist`, `build`, `target`) never appear.
- **CodeMirror source editing** — Markdown files open in a source editor showing the real Markdown text.
- **Safe save (`Ctrl+S`)** — saves go through the Rust backend, not unrestricted frontend filesystem access:
  - atomic: temp file on the same volume, flushed and synced, then renamed over the target; a failed write never destroys the original;
  - no silent overwrite: if the file changed on disk since it was read (mtime/size), the app refuses to overwrite and presents **Reload / Keep** instead;
  - round-trip fidelity: LF files stay LF, CRLF files stay CRLF, and a UTF-8 BOM is preserved exactly; invalid UTF-8 is rejected rather than silently rewritten.
- **Unsaved-switch guard** — switching to another file while a draft is dirty asks before discarding it.
- **Explicit Refresh** — re-scans the root directory so externally added/removed Markdown files are picked up.

## Deferred (not in v0.1)

- No file watcher — the tree only updates on explicit Refresh.
- No multi-mount Workspace — exactly one root directory per session; no workspace persistence.
- No Preview — no Markdown rendering or side-by-side view.
- No tabs — one document open at a time.
- No Properties panel — no per-note metadata.
- No indexing — no full-text search, graph, or database.
- No LaTeX (`.tex`) support yet.
- No AI features.
- No app-close confirmation guard — quitting with an unsaved dirty draft will lose the edit (switching files is guarded, closing the window is not).

## Notes for the Human Reviewer

The automated suite (`pnpm verify`) covers the Rust filesystem layer, the typed IPC contracts, and the frontend flows. A desktop launch was required for the remaining checks.

## Manual Smoke Test Evidence (Windows 11, 2026-08-27)

The 13-step checklist in `README.md` was run on a real desktop session and passed:

- 1-4: App launched (`pnpm tauri dev`); opened `tests/fixtures/simple` via the native folder picker; `README.md` and `Notes/hello.md` appeared; `ignored.txt` did not.
- 5-8: Opened `hello.md` in the CodeMirror source editor, edited and saved with `Ctrl+S`; the file on disk remained ordinary Markdown.
- 9-10: Modified `README.md` externally while dirty in the app; saving refused with the conflict message and did **not** overwrite the external change.
- 11-12: CRLF fixture stayed CRLF (6 CR, 6 LF) and the BOM fixture kept its `EF BB BF` bytes after edit+save.
- 13: `Refresh` picked up an externally added Markdown file and removed it after external deletion.

Known gap documented in Supported: no app-close confirmation guard (window close with a dirty draft loses the edit; file-switch is guarded).
