# v0.2 Workspace & File Manager — Design

Date: 2026-08-27
Status: Approved (brainstorming session)

## Goal

Extend the v0.1 single-folder foundation into a multi-mount Workspace with real file management: users compose several existing local directories into one Workspace without moving files, manage per-mount permissions and exclusions, and perform safe create/rename/move/trash operations — with a live file watcher and persistent Workspace configuration.

## Architecture

- **Frontend (React + TypeScript + Zustand):** Workspace view (mount management panel + aggregated file tree grouped by mount), file-operation entry points (new folder / new markdown / rename / delete-to-trash / cut & paste within a single mount), welcome screen (new / open / recent workspaces), read-only and missing-file state display. Frontend keeps treating paths as opaque strings.
- **Rust:** `workspace` module (Workspace config read/write: AppData JSON holding mounts, per-mount permissions, exclusion rules, recent-workspace list), extended `files` commands (create / rename / move / delete via system Trash), and a `watcher` module (Rust `notify` recursive watching, one watcher per mount, honoring exclusion rules, 300 ms debounce, emitting create / remove / rename / rename-from events).

## Confirmed Decisions

| # | Decision area | Choice |
|---|---------------|--------|
| 1 | Workspace config location | AppData `<AppData>/<app>/workspaces/<id>.json`; no DB (SQLite stays v0.7) |
| 2 | File watcher | Full Rust `notify` recursive watch, live propagation to frontend |
| 3 | Multi-mount UI | Workspace view: mount management panel + aggregated file tree (grouped by mount); looks like v0.1 when single-mount |
| 4 | File operations | Core set: new folder, new markdown, rename, delete-to-system-Trash, cut & paste move within a single mount; no drag & drop, no cross-mount move |
| 5 | Trash | Rust `trash` crate → OS Recycle Bin |
| 6 | Link rewriting | NOT done in v0.2 (no link index yet); documented in release notes; revisit in v0.5 |
| 7 | Recent workspaces | AppData JSON, most recent 8; welcome screen lists them for one-click open |
| 8 | Exclusion rules | Part of Workspace config; default full set from spec §6.3 (`.git, node_modules, dist, build, target, .venv, venv, .cache, coverage`); UI view/edit; per-mount override supported |
| 9 | Read-only mounts | Three-layer defense: UI disables operations + Rust commands verify mount permission (return PermissionDenied) + tree shows read-only marker |
| 10 | Watcher coordination | One watcher per mount, honors exclusion rules, 300 ms debounce merging events, manual Refresh kept as forced full rescan |
| 11 | Document following | Watcher rename event drives the open document to its new path; delete → existing "file missing on disk" state |
| 12 | Removing a mount | Dirty documents hit the unsaved-changes guard; otherwise their documents close; tree branch disappears immediately |
| 13 | Workspace lifecycle | Welcome screen: New Workspace (name + first mount) / Open Existing / Recent list; in-app "switch workspace" returns to welcome (dirty guard first) |

## Data Model

### WorkspaceConfig (AppData JSON, versioned)

```json
{
  "schemaVersion": 1,
  "id": "uuid",
  "name": "Personal Workspace",
  "mounts": [
    { "path": "D:\\Notes", "permission": "read-write" },
    { "path": "E:\\Archive", "permission": "read-only" },
    { "path": "D:\\Old\\Scratch", "permission": "excluded" }
  ],
  "exclusions": [".git", "node_modules", "dist", "build", "target", ".venv", "venv", ".cache", "coverage"]
}
```

- `permission` ∈ `"read-write" | "read-only" | "excluded"`.
- `exclusions` is the mount-level default; per-mount override allowed (a mount may carry its own `exclusions` array).
- Schema-versioned (spec §44); migration path = detect old version, back up, migrate, validate, switch.
- Paths stored as absolute, platform-native strings. No absolute-path assumptions baked into logic.

### RecentWorkspaces (AppData JSON)

```json
{ "recent": ["C:\\path\\a", "D:\\path\\b"] }
```

- Cap 8 entries, most-recent first, de-duplicated by canonical path.
- Stored separately from the workspace config files (a recent entry is a *path to a workspace config*).

## Rust Modules

```
src-tauri/src/
  workspace/
    config.rs      // WorkspaceConfig model, load/save/migrate, AppData paths
    recent.rs      // recent-workspace list (AppData JSON)
    permissions.rs // mount permission lookup + enforcement helper
  filesystem/
    scanner.rs     // v0.1 scanner, extended: takes exclusions; no hardcoded-only ignores
    ops.rs         // create folder / create markdown / rename / move / delete-to-trash
    writer.rs      // v0.1 atomic save (unchanged)
  watcher/
    mod.rs         // per-mount notify watchers, exclusion filtering, debounce
    events.rs      // WatcherEvent enum (created / removed / renamed {from,to})
```

- Scanner change: v0.1 hardcoded the five ignores; v0.2 makes the ignore list a parameter (defaults to config exclusions). The default must still include the v0.1 five so no regression.
- `ops.rs` delete uses the `trash` crate; rename/move are `fs::rename` with same-volume care (reuse writer's Windows rename findings); move validates target mount permission and same-mount constraint.

## Tauri Commands (thin wrappers)

| Command | Input | Output / Error |
|---------|-------|----------------|
| `create_workspace(name)` | string | `WorkspaceConfig` |
| `open_workspace(id)` | string | `WorkspaceConfig` + aggregated tree |
| `list_workspaces()` | — | `WorkspaceInfo[]` |
| `add_mount(config_id, path, permission)` | — | updated `WorkspaceConfig` |
| `remove_mount(config_id, path)` | — | updated `WorkspaceConfig` |
| `set_mount_permission(config_id, path, permission)` | — | updated `WorkspaceConfig` |
| `update_exclusions(config_id, exclusions)` | — | updated `WorkspaceConfig` |
| `scan_root(root, exclusions)` | — | `FileTreeNode[]` (extended from v0.1) |
| `create_folder(parent, name)` | — | new path |
| `create_markdown(parent, name)` | — | new path |
| `rename_path(path, new_name)` | — | new path |
| `move_path(path, target_dir)` | — | new path (same mount only) |
| `delete_to_trash(path)` | — | ok |
| `watch_workspace(config_id)` | — | starts per-mount watchers; events pushed via Tauri events |
| `stop_watching()` | — | ok |

Permission enforcement: every mutating command resolves the mount for its target path and returns `PermissionDenied { path }` if the mount is not `read-write`; the frontend also disables the corresponding UI in read-only mounts (three-layer defense).

## Watcher Event Flow

```
Rust notify (per mount, exclusion-filtered)
  → debounce 300ms, merge bursts
  → emit Tauri event: { kind: "created"|"removed"|"renamed", path, to? }
  → frontend watcherBridge:
       created/removed → refresh affected subtree (or full tree for simplicity in v0.2)
       renamed → if path === activeDocument.path → editor follows to `to`;
                 else refresh tree
       removed → if path === activeDocument.path → fileMissing = true (existing state)
  → manual Refresh button still triggers full rescan
```

## Error Handling

Reuse the v0.1 `AppError` enum, adding variants as needed:

```
MountNotFound { path }
DuplicateMount { path }
WorkspaceNotFound { id }
InvalidWorkspaceConfig { id }
CrossMountMoveNotAllowed
DeleteFailed { path }   // trash failure
```

User-facing messages follow the spec §26 rule: what happened / which file / data safe? / what next.

## Testing Strategy

- **Rust unit/integration (tempfile):** config load/save/migrate round-trip; recent-list cap/dedupe; scanner honors exclusions (default set + custom); permission enforcement on every op; create/rename/move/delete happy paths; delete-to-trash uses a mocked/abstracted trash boundary (spec §32.2: "delete to trash（可 mock/抽象）"); rename/move same-mount guard; watcher exclusion filtering and debounce (via a testable debouncer with injectable clock); cross-mount move rejection.
- **Watcher:** event-generation tests use `tempfile` + notify against a real temp dir where practical; debounce logic unit-tested with a fake clock.
- **Frontend (vitest):** workspaceStore lifecycle (new/open/switch, dirty guard on switch, mount add/remove behavior, document-follow on rename); MountManager interactions; FileTree read-only markers; fileOps wrappers assert exact command names/args; watcherBridge maps events to store updates.
- **No tests touch real user directories** (spec §32.2).

## Scope Boundaries (explicitly deferred)

- Link rewriting on rename/move (v0.5, needs link index).
- Drag & drop; cross-mount move; multiple-item selection operations.
- SQLite / indexing / search (v0.7).
- Binary/large-file filtering in watcher.
- Fine-grained permission UI beyond the three mount states.
- App-close confirmation guard (still open from v0.1; tracked separately).

## Known Risks

- **notify cross-platform quirks** on Windows (rename events split into remove+create, or as `rename` with from/to) — mitigate with the debounce+merge and a rename-event unit/integration test, and document platform behavior in release notes.
- **Mount removal while watchers active** — stop the mount's watcher before config change commits.
- **Scanner regression** — default exclusion set must keep the v0.1 five ignores; a test pins this.
- **Recent list growth** — cap enforced in the store layer with a test.

## Acceptance Criteria (v0.2)

- A user can compose multiple existing local directories into one named Workspace without moving files.
- Mounts support read-write / read-only / excluded; read-only mounts refuse file operations in UI and in Rust.
- New folder, new Markdown, rename, delete-to-system-Trash, and same-mount cut & paste move all work against real files.
- Deleted files land in the OS Recycle Bin.
- Default exclusions apply; users can view/edit them per workspace.
- External file changes appear in the tree live (watcher) and via manual Refresh.
- Renaming/moving an open document follows it to the new path; deleting it shows the missing-file state.
- Recent workspaces persist and one-click reopen.
- `pnpm verify` passes with fresh output; manual smoke checklist updated and run on Windows 11 before v0.2.0-alpha is tagged.
